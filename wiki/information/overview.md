# Overview

`mcp-rag-mcp-server` is a [Model Context Protocol](https://modelcontextprotocol.io) server
that exposes the MCP RAG knowledge base to MCP compatible clients: Claude Desktop, IDE
assistants, and anything else that speaks the protocol.

It is a thin adapter. It holds no state, no cache and no logic of its own. Every tool is one
call to the Express backend in
[`LXVault/server-expressjs`](https://github.com/LXVault/server-expressjs), which owns the
data, the permissions and the audit log.

## Why the token matters

The server authenticates with a **per project access token**, generated by a person on the
web app's Access Tokens page. A user holds at most one active token per project.

That single fact is what makes an assistant's actions accountable:

* **The token names the project.** No tool takes a project argument, so an assistant cannot
  reach a project the token was not issued for.
* **The token names the user.** The backend resolves the acting user from it and records
  every call in its audit log, so an action taken by an assistant is attributable to the
  person whose token it used.
* **The token decides permission.** Owner and admin checks happen in the backend against
  that user. An assistant cannot claim a role in an argument, which means a prompt injected
  tool call cannot escalate privileges or act on someone else's project.

## What it exposes

Nine tools, in three groups:

**Identity.** `whoami` and `get_project` report who and what the token is bound to, and
`get_project` also reports how much of the knowledge base the project's current embedding
model can search. Neither needs an OpenRouter key.

**Knowledge.** `search_knowledge` ranks chunks by meaning, `add_knowledge` saves text as a
new chunk, and `upload_file` ingests a `.md`, `.txt` or `.pdf`. All three embed text, so
they spend the acting user's own OpenRouter credits and fail with a clear message when that
user has no key configured.

**Project management.** `create_new_project`, `change_project_title`,
`change_project_description` and `add_member`. The backend gates each on owner or admin.

Every tool, its arguments and what it returns: [../reference/tools.md](../reference/tools.md).

## What it is not

It does not run a model, generate text, or decide anything. The assistant on the other end
of the protocol does that. This server carries requests to an API and carries answers back.
